E4-01　定 P6 與 P9

已合併不連交易所無依賴

epic 寫明開工前要定的兩件事。只改 PROTOCOL 與 DECISIONS。

  • P6。 worker 一結束就寫 DEAD 的話，conn worker crash 會讓 controller 結束這條連線上所有 session。另一種是自動重拉期間維持 PENDING，放棄才寫 DEAD。定一種，寫進 §3.5。
  • P9。 conn worker 的版本放在 controller 的部署設定，還是 etcd 裡一個 key；換版時怎麼排程換 incarnation（D106）。E9 的 artifact 管線做好之前，md-agent 執行 repo 建出的 binary。這條過渡也寫進去。
  • P14 不在這張定。subject 維持現在的拼法。

完成：P6、P9 從 §10 的待定清單移出，內容寫進正文。

E4-02　md.f 的 envelope

已合併不連交易所無依賴

contract/wire/envelope 現在只有 v1 的偏移：32 byte，version、len、md_ts_ns、conn_epoch、seq。編碼與解碼還沒有。套件說明寫著 shape only。

  • 寫入與讀取這 32 byte。讀取端用 len 跳到 payload，之後加長 envelope 也不破。
  • 不碰 NATS。protobuf 的 FeedEvent 接在後面，這張票不組 subject。

完成：來回寫一次，欄位不變；len 較長的後代版本，v1 的讀取端能跳過自己不認識的尾巴。

E4-04　連線、訂閱 diff、解碼、md.f

已合併不連交易所依賴 E4-02

一顆 conn worker：一條 websocket，身分是 (venue, route, n)。交易所的差異走 E3 的 Market／Session。Ping／Pong 與 MaxLifetime 已經在 exchange/transport/ws，這張票呼叫它，不重寫。

  • 照 desired 清單做 subscribe／unsubscribe 的 diff。送出節奏遵守 SessionLimits。
  • Decode 進 Sink。trade 這類非簿事件編成 FeedEvent，前面加上 envelope，發到 md.f.{inst}.{topic}.{ticker}。
  • seq 在同一個 (feed, conn_epoch) 裡從 1 連續。重連時 conn_epoch 加一，seq 重新從 1。
  • 斷線由 worker 重撥。adapter 不重連。
  • 用錄下來的 session 與假的 websocket 測，不連交易所。訂單簿的 fold 不在這張。

完成：重播一條 trade session，訂閱只送出差異，發出的 seq 連續；模擬斷線重連後 conn_epoch 加一。

E4-13　conn_epoch 經 shim 交給下一個行程

已合併不連交易所依賴 E4-04

mftiko-md-conn 在 fd 3 上說 C4，幀格式跟 shim 已經在說的那套一樣。InitPayload.conn_epoch 是上次上報的號，0 表示還沒有上報過，第一次撥號用 1。proto 與 PROTOCOL §6.2 一起改，mdctl 仍是草案。

  • 收 Init、Start，送 Hello、Beat、Report。
  • 同一個行程裡重連，或新行程第一次撥號：先把新號寫進 Report，寫完才撥，md.f 才用這個號。撥不上不消耗。
  • 不寫 etcd。shim 退出之後這份快照就沒了，下一次從 1 起。
  • agent 讀 Report、在 Release 之後寫進下一次 Init，是 E4-08。

完成：Init 帶 N 時，對端在第一次撥上之前就收到 conn_epoch N+1。同一個行程斷線重連，下一個號同樣先到對端。用假的 C4 對端測，不連交易所。

E4-05　本地訂單簿

可以做不連交易所依賴 E4-04

不管策略訂的是 orderbook 還是 orderbook_delta，worker 都維護一本本地全量。兩個 topic 對到同一個 atom。快照不經過 md.fetch。

  • SnapshotREST（Binance 現貨、BinanceUM）：先緩衝增量，在進程內跑 PublicREST.Depth，丟掉 snapshot 已經涵蓋的更新。檔數用 BookSync.Depth（現在是 1000）。
  • SnapshotStream（Bybit、OKX）：訂閱後的第一則就是全本。這兩家的 REST Depth 不參與同步。
  • BookSync.Check 判斷套用、略過或重抓。斷號或 checksum 失敗就丟掉本地本、重抓，然後推一則 reset，內容是完整的 book。
  • orderbook 推 top-N 全量，top-N 有變才推。N 是這個 MD instance 的設定，同一個 venue 上固定。orderbook_delta 推正規化增量，數量 0 表示刪除該檔。

完成：Binance 的錄製 session 加上一份 depth fixture，結束時本地本與 snapshot 一致；抽掉一筆更新會重抓並發出 reset。Bybit 或 OKX 的錄製 session 用串流裡的全本對齊，不打 REST。

E4-06　tape ring 與 md.view

可以做不連交易所依賴 E4-04；訂單簿的回覆等 E4-05

晚加入的人先訂 md.f，再向持有這顆 atom 的 worker 要 md.view。

  • 只錄 trade、aggtrade、liquidation。錄不錄由 topic 決定，agent 寫在 AtomAssignment.record。book 不錄。
  • 每個 atom 一個 ring，存已經發出去的位元組（envelope 加 FeedEvent），回覆時不再編碼。上限是時間窗加筆數，再加 worker 的總上限。
  • websocket 重連時在 ring 裡記一個 gap。
  • md.view.{inst}.{topic}.{ticker}：trade 類回 tape 分頁，由新到舊，游標是 (conn_epoch, seq)，每頁小於 1 MiB。orderbook_delta 回 seq S 時的 book。沒有 responder 就是沒有 worker 持有這顆 atom。
  • tape 跟著行程與 atom。linger 結束或行程被換掉，tape 就沒了。不寫 Redis。

完成：先訂 md.f 再讀 view，接縫上沒有缺口、也沒有重複套用 seq ≤ S 的增量。重連後的 tape 帶著 gap。book 的 view 回的是該 seq 的全本。

E4-07　md.fetch

已合併不連交易所依賴 E4-03

無狀態服務，每個 region 一個 NATS queue group。任何 replica 都能回答。沒有 agent、沒有 lease、不落庫。

  • 只轉發公開 REST：Klines，以及交易所不推送、只能查詢的值（BinanceUM 的 open interest）。
  • 用 E3 的 PublicREST 與 fasthttp Doer。測試用錄下來的回應。
  • 訂單簿的快照不走這裡。best quote 這類有推送的值走 feed，不輪詢。

完成：對一個假的 REST 來源，K 線分頁與 open interest 各回答一次；兩個 replica 在同一個 queue group 裡，一則請求只有一個回答。

E4-08　md-agent

可以做不連交易所依賴 E4-01、E4-04、E4-13，以及 E1 的收養

需求項目進來之後，agent 把它變成連線上的 atom。controller 不展開。這張票不讀 session spec。

  • feed key 仍是 <topic>.<UniversalTicker>。用已載入的商品表 Resolver.Get 解成 UID。找不到、已下架、已到期，或不是 TRADABLE，ack 是 REJECTED。之後放置與事件身分用 UID；要欄位時用 GetByUID。
  • Market.Atom 給出 route 與 channel。atom id 維持 <venue>:<route>:<channel>。多個 feed 可以共用一個 atom，refcount 是 owner 集合的大小，不是計數器。owner 是 (session, feed)。
  • 新 atom 放進同一個 (venue, route) 裡還有空間、n 最小的連線。放滿才開 n+1。放置有黏性，記在 etcd，重啟後沿用。不整併。
  • owner 歸零後等 linger（預設 5 秒）再退訂。最後一個 atom 退訂就停掉那顆 worker。不另設連線的 linger。
  • ack 寫回需求項目。重啟時 list 需求前綴，重建 owner 集合，收養 shim 還活著的 conn worker，連線不斷。
  • 重拉已結束的 conn worker 時，先從舊 shim 的最新 Report 讀 conn_epoch，Release 之後的 Init 帶這個號（E4-13）。shim 已經不在就從 0 起。
  • E9 之前，spawn 的是 repo 建出的 binary，版本規則依 E4-01。

完成：手寫兩筆需求，其中一筆與另一筆落在同一個 atom，只訂閱一次。拿掉一筆，linger 之後才退訂。agent 行程換掉之後，conn worker 還在，新 agent 看得到它。連線崩潰後重拉，新行程的 Init 帶著舊 shim 最後上報的 conn_epoch。
